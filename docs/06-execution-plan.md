# 总体执行计划

按 MVP 目标拆出可落地的里程碑顺序。每个阶段结束都应该有一个"能跑起来的东西"，而不是攒到最后才集成。

## 阶段 0：工程骨架（0.5 天）

- [ ] 创建 `backend/`、`frontend/`、`deploy/` 目录
- [ ] 后端：FastAPI 项目骨架 + 健康检查接口 `/api/health`
- [ ] 前端：Vite + React + TS 骨架，跑通一个空白页面
- [ ] 数据库：本机/开发环境起一个 MariaDB，能连通

## 阶段 1：账号体系（1-2 天）

- [ ] `users`/`merchant_profiles`/`model_profiles` 表 + 迁移
- [ ] 注册/登录/JWT 鉴权接口
- [ ] 前端登录/注册页 + 角色路由守卫
- [ ] 个人资料编辑 + 实名认证提交/审核接口

## 阶段 2：订单核心闭环（3-5 天，核心阶段）

- [ ] `orders`/`order_logs`/`order_messages` 表
- [ ] 状态机 service 层 + 全部订单流转接口
- [ ] 抢单原子更新逻辑 + 并发测试
- [ ] 商家端：发布订单、我的订单、订单详情
- [ ] 达人端：抢单大厅、我的订单、订单详情
- [ ] 图片/文件上传接口（样品图、素材）

## 阶段 3：资金闭环（2-3 天）

- [ ] `wallets`/`wallet_transactions`/`withdrawals` 表
- [ ] 订单完成触发结算的事务逻辑
- [ ] 提现申请/审核/登记转账接口
- [ ] 达人端：钱包页、申请提现页
- [ ] 管理员端：提现审核页
- [ ] 余额一致性校验脚本

## 阶段 4：管理后台与争议处理（1-2 天）

- [ ] 管理员端：用户管理、订单监控、争议列表+仲裁、数据看板
- [ ] 后端对应接口

## 阶段 5：部署上线（1 天）

- [ ] 按 `05-deployment.md` 走一遍服务器配置
- [ ] 首次部署 + 冒烟测试（走一遍完整业务闭环：发单→抢单→寄件→拍摄→寄回→验收→结算→提现审核→登记转账）
- [ ] 配置备份和基础监控（至少能收到进程崩溃/磁盘满的告警，比如简单的 crontab 检查脚本+邮件/webhook 通知）

## 预估总工期

约 9-13 个工作日（单人开发，MVP 范围）。如果需要更快上线，优先级建议：阶段 0-2（账号+订单闭环）不可压缩，阶段 3 资金闭环次之，阶段 4 管理后台可以先做最小可用版本（比如先不做数据看板，只做列表和审核按钮）。

## 后续可迭代方向（明确排除在本轮 MVP 之外）

- 接入真实支付网关（微信支付/支付宝支付），实现自动化提现
- WebSocket 实时推送（抢单大厅秒抢体验、订单状态变更通知）
- 对象存储（OSS/COS）替代本地磁盘存储上传文件
- 达人评分/信用体系，商家评价
- 站内即时聊天替代简单留言板
- 平台抽佣比例配置化
- 完整 CI/CD 流水线
- 数据统计报表增强（导出 Excel、多维度分析）
