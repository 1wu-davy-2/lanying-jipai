# UI 重设计实施契约

本文件适用于 `tasks/` 下全部任务。任何任务文档没有重复写出的规则，也必须遵守本契约。

## 1. 开始前

1. 阅读 `AGENTS.md`、`docs/ui-redesign/01-prd.md`、本文件和当前任务全文。
2. 执行 `git status --short`，记录已有改动。已有改动视为他人工作，不得删除、覆盖或回退。
3. 阅读任务列出的现有实现和对应测试，确认当前路由、API、状态与交互。
4. 只处理一个任务，不提前实现后续任务，不顺便修复无关问题。

## 2. 不可改变的边界

- 不修改后端、数据库、迁移、API 契约、鉴权、角色、路由、查询 key 或业务状态机。
- 不新增依赖，不替换 React、Ant Design、图标库、状态管理或请求层。
- 不新增页面、导航项、业务字段、虚构数据、收益承诺、审核承诺或隐私承诺。
- 不改变 Android `webDir`、包名、HTTPS、强制更新和网络配置。
- 不删除或弱化现有测试断言来获得通过；视觉文案断言可随明确需求更新。
- 不提交、推送或清理不属于当前任务的文件，除非任务明确要求。

## 3. 代码与视觉约束

- 继续使用现有 `@ant-design/icons`。熟悉操作使用图标；不使用 emoji、Unicode 箭头或自制功能 SVG。
- 品牌标记是唯一允许的定制矢量，复用现有鹰羽勾形轮廓。
- 新颜色、字号、间距、圆角和层级必须来自 PRD 令牌；不在 JSX 中新增固定视觉内联样式。
- Card 只用于单个重复对象或真实工具容器；禁止页面区块卡片套卡片。
- 页面只有一个视觉主操作；危险操作有二次确认并说明影响对象。
- 所有动态区域预留稳定尺寸，加载、长标题、状态标签和错误文本不得引发布局跳动或遮挡。
- 组件文案使用简体中文，语气直接、尊重、可核对，不以用户性别或身份昵称用户。

## 4. 测试顺序

每个任务至少执行：

```powershell
cd frontend
npm test -- <本任务相关测试文件>
npm run build
```

任务影响共享壳层、主题、状态组件或全局 CSS 时，再执行：

```powershell
cd frontend
npm test
```

Android 同步仅在 T11/T12 且已具备 `.env.android`、JDK 21 和 Android SDK 时执行：

```powershell
cd frontend
npm run android:sync
```

缺少环境时不要伪造成功，反馈缺失条件即可。

## 5. 页面检查方式

页面检查不得安装、下载或新增 Playwright、Chromium、浏览器驱动或其他自动化浏览器依赖，包括但不限于：

```text
npm install playwright
npx playwright install
pip install playwright
playwright install chromium
```

也不得为了截图修改 `package.json`、`package-lock.json` 或 Python 依赖。不要运行可能触发浏览器下载的命令。

允许的检查顺序：

1. 使用环境已经提供的内置浏览器能力，不安装任何东西。
2. 使用开发者或测试人员已经打开的本地浏览器进行人工检查。
3. 使用 Android 真机或已经存在的模拟器检查 WebView，不新建或下载模拟器镜像。
4. 若以上均不可用，完成单测、构建和静态 CSS/DOM 检查，并在反馈中明确写“可视化验收未执行：环境无现成浏览器或设备能力”。

不得用源代码推测替代截图结论。截图存在时保存到任务约定的临时或交付目录，并反馈路径；仓库未要求提交截图时不要将其加入 Git。

## 6. 视口检查清单

每个用户页面至少检查 390x844 和 1440x1000；涉及壳层、表格或表单时增加 360、412、768 和 1024px。

- 页面无水平滚动条，表格例外只能发生在明确的内部滚动容器。
- 顶栏、底部导航、固定操作和安全区不遮挡正文。
- 最长标题、最长状态、空状态、错误状态和加载状态不改变整体宽高结构。
- 主按钮、返回、上传、Tab、筛选、弹层关闭和表单提交可操作。
- 文本、图标、图片和金额不重叠；触控目标至少 44x44px。
- Android 检查软键盘、系统返回、网络失败图片和安全区。

## 7. 变更自检

任务结束前执行：

```powershell
git status --short
git diff --check
git diff --stat
```

逐项确认：

- 只有任务允许的文件发生变化。
- 没有远程纹理、无授权图片、密钥、账号、构建产物或本地配置被提交。
- 没有出现新的英文状态枚举、假数据、未实现链接或 `TODO` 占位。
- 没有新增 Playwright 或浏览器相关依赖和锁文件变化。

## 8. 任务派发话术

将 `Txx` 替换为实际任务编号后，可直接使用以下文字派发任务：

```text
请只执行 docs/ui-redesign/tasks/Txx-*.md 定义的任务。开始前完整阅读 AGENTS.md、docs/ui-redesign/01-prd.md、docs/ui-redesign/02-execution-contract.md 和该任务文档。严格限制在“允许文件”内，保留工作区已有改动，不修改路由、API、权限、状态机或 Android 容器，不新增依赖。按任务要求运行测试和构建；页面检查只能使用环境现成的浏览器或人工设备，不得安装或下载任何浏览器自动化依赖。完成后停止扩展，不进入下一任务，并按实施契约第 9 节模板完整反馈给主审。
```

## 9. 完成反馈话术

执行完成后，停止继续扩展，不要只回复“已完成”。请将下面模板完整反馈给主审；没有内容的项目填写“无”。

```markdown
### 任务反馈

- 任务编号：Txx
- 完成状态：完成 / 部分完成 / 阻塞
- 修改文件：逐项列出相对路径
- 完成内容：按页面或组件列出可见变化
- 保持不变：确认路由、API、权限、状态机和 Android 容器是否未变
- 测试结果：列出实际执行的命令、通过数量和失败摘要
- 页面检查：列出设备/视口、检查页面与结果；未执行时写明原因
- 截图路径：列出实际存在的路径；没有则写“无”
- 未完成项：列出未实现或无法核验的内容
- 风险与冲突：列出发现的业务文档冲突、已有改动或回归风险
- 建议下一任务：只写任务编号，不提前实施
```

最后附上一句：

> 本任务已停止扩展，等待主审检查后再进入下一任务。
