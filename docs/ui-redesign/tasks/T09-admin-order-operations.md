# T09 管理端订单运营

## 目标

重做运营发单、接单申请、订单监控和争议处理四个高频页面，使待处理对象、风险和单项操作更清晰。保留当前管理员权限、审核主体、发布字段、订单详情路径和争议结果。

## 依赖与允许文件

- 依赖：T01、T03；商家订单详情共享 T08 组件时，先确认 T08 已完成。
- 允许修改：`frontend/src/pages/admin/AdminOperationsPage.tsx`、`frontend/src/pages/admin/AdminApplicationsPage.tsx`、`frontend/src/pages/admin/AdminOrdersPage.tsx`、`frontend/src/pages/admin/AdminDisputesPage.tsx`、对应测试、`frontend/src/styles/admin-orders.css`。本页面断点写在该模块末尾。
- 不允许修改：管理 API、审核/发布 payload、分页、状态枚举、路由、`MerchantOrderWorkspacePage` 或后端权限。

## 通用布局

- 页面标题区包含标题、最多一句说明和唯一主操作；待处理数量可用中性计数标签，不用营销指标卡。
- 桌面筛选条高 40px，可换行但不改变控件顺序；搜索、Select、Switch 使用对应控件与现有值。
- 桌面表格保留高密度扫读，表头使用中性背景，操作列固定在可见范围；英文状态统一映射为中文。
- 390px 使用可展开摘要项：主对象+状态、关键风险/金额/时间、单项操作，不压缩完整表格。

## 页面要求

### 运营发单

- 订单列表与发布入口保持现有行为；发布表单视觉分组与 T08 一致。
- 商家选择、商品来源、多名额、补贴、押金、素材和时限字段不能遗漏或改变默认值。
- 草稿/发布中/失败反馈使用稳定状态，不重复提交。

### 接单申请

- 按父订单分组的关系保持；组标题显示订单、申请数、剩余名额。
- 每位申请者显示头像/昵称、等级、实名状态、申请留言、同款图和申请时间。
- 待审核仅显示“通过/拒绝”一组操作；审核中禁用重复点击，拒绝原因按现有字段提交。
- 多人隐私：一位申请者的同款图、留言与审核原因不能串到其他申请者。

### 订单监控

- 保留状态、关键词、仅超时筛选；“仅超时”继续使用 Switch。
- 列表显示订单、佣金、中文状态、创建时间和超时风险；点击仍进入 `/admin/orders/:id`。
- 未知状态显示中性中文回退，不直接输出英文枚举。

### 争议处理

- 清楚区分旧订单争议与新履约争议，但不使用紫色等随意业务色作为唯一依据。
- 显示争议对象、达人名额、当前状态、原因、证据入口和处理动作。
- 处理弹层明确影响父订单还是单个履约；提交结果和备注字段保持不变。

- 手机端能查看和处理单个对象，不需要滚动整个页面宽度。
- 相关测试、全量测试和构建通过。
