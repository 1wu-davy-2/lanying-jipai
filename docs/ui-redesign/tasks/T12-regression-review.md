# T12 全量回归与交付审查

## 目标

在所有实施任务完成后，统一检查功能边界、视觉一致性、响应式、测试、Android 容器和交付物。本任务以发现并报告问题为主，不进行无边界重构。

## 依赖与允许文件

- 依赖：T01-T11 全部完成并通过主审。
- 默认只允许修改测试、明确的视觉回归小问题和本目录交付记录。
- 发现业务、API、权限或状态机问题时停止修复并反馈，不得扩大为后端任务。

## 1. 工作区与契约检查

- [ ] 运行 `git status --short`、`git diff --stat`、`git diff --check`。
- [ ] 确认没有后端、迁移、API 契约、路由、查询 key、权限或状态枚举的非授权变化。
- [ ] 确认没有新增依赖、浏览器二进制、构建产物、APK、本地配置、账号或密钥。
- [ ] 搜索远程纹理/品牌图片 URL、旧主色硬编码、`蓝影寄拍`、英文状态直出、emoji、Unicode 箭头和固定 `window.innerWidth` 宽度。

建议命令：

```powershell
rg -n "蓝影寄拍|unsplash\.com|transparenttextures\.com|window\.innerWidth" frontend/src frontend/public frontend/android
rg -n "style=\{\{" frontend/src -g "*.tsx"
git diff -- frontend/package.json frontend/package-lock.json backend
```

业务产生的动态内联值可保留，固定颜色和尺寸必须说明原因或迁入 CSS。

## 2. 自动化验证

```powershell
cd frontend
npm test
npm run build
```

- 记录测试文件数、测试数、构建耗时、产物大小和既有大包警告。
- 不因视觉改版删除或弱化业务断言。
- 若后端无改动，至少确认 `git diff -- backend` 为空；环境现成时可运行后端全量测试，但不得为此重建或下载大体积环境。

Android 条件满足时：

```powershell
cd frontend
npm run android:sync
cd android
.\gradlew.bat test
.\gradlew.bat assembleDebug
```

先确认 `.env.android`、JDK 21 和 Android SDK 已存在。任何缺失都应报告，不得下载 SDK、模拟器镜像或浏览器依赖。

## 3. 页面矩阵

使用已有浏览器或人工设备逐一检查，禁止安装或下载 Playwright/Chromium。每页至少检查正常、加载、空、错误和一个关键业务状态。

| 角色 | 页面 |
| --- | --- |
| 公共 | `/entry`、三种登录、达人注册；官网组件单独预览但不改根路由 |
| 达人 | 大厅、详情/申请、榜单、我的订单、新履约详情、旧详情、钱包、提现、资料、入驻两步 |
| 商家 | 订单列表、发布弹层、多人履约工作台、店铺资料 |
| 管理 | 运营发单、申请审核、话术库、看板、用户、订单监控、争议、提现 |

视口：360x800、390x844、412x915、768x1024、1024x768、1440x1000。Android 另查安全区、软键盘、系统返回、图片失败和启动图。

## 4. 核心流程抽查

只使用现有测试数据和账号，不在文档记录凭据：

1. 达人注册 -> 完善资料 -> 提交实名 -> 审核状态。
2. 浏览大厅 -> 查看三种商品来源 -> 提交申请 -> 运营审核。
3. 多名额订单 -> 独立物流 -> 素材版本 -> 驳回修订 -> 验收 -> 结算。
4. 钱包核对 -> 提现申请 -> 运营通过/驳回/登记转账。
5. 商家查看多个名额，确认看不到跨名额混合信息；达人确认看不到其他达人信息。

不得为了完成抽查改变数据库规则或伪造前端成功状态。后端未启动或无测试数据时，列出未覆盖流程。

## 5. 视觉一致性清单

- [ ] 品牌名、鹰羽标记、favicon、Android 图标和启动图一致。
- [ ] 主按钮、成功、金额、警告、危险和信息色语义一致，文本对比度达到 AA。
- [ ] 同类页面的标题、筛选、状态、空/错/加载和主操作位置一致。
- [ ] 不存在卡片套卡片、装饰性渐变/光斑、过大圆角或营销式工作台布局。
- [ ] 真实商品/作品/素材图不被模糊、过裁切或无关占位替代。
- [ ] 360px 无文本重叠；底栏、粘性操作和安全区互不遮挡。
- [ ] 手机没有整页横向滚动；桌面表格保持可扫描。
- [ ] 触控目标、焦点、键盘、reduce motion、alt 和 aria-label 合格。

## 6. 验收与缺陷分级

- P0：权限、隐私、金额、状态转换或数据损坏，立即停止发布。
- P1：主流程无法完成、按钮被遮挡、关键页面空白、Android 无法启动，修复后重新全量验证。
- P2：局部溢出、错误层级、状态不一致、图片失败占位缺失，进入当前发布修复清单。
- P3：不影响理解和操作的细节，记录后排期，不在本任务无限打磨。
