# T04 达人订单大厅与申请详情

## 目标

重做达人浏览和申请订单的视觉层级，让手机用户快速判断“能否申请、能赚多少、商品怎么来、要交付什么、多久完成”，不改变查询、轮询、筛选、分页、资格或申请逻辑。

## 依赖与允许文件

- 依赖：T03。
- 允许修改：`frontend/src/pages/orders/ModelHallPage.tsx`、`frontend/src/pages/orders/MarketplaceOrderDetailPage.tsx`、对应测试、`frontend/src/styles/talent-marketplace.css`。本页面断点写在该模块末尾。
- 允许新增：仅限这两个页面共用的纯展示组件及测试。
- 不允许修改：`api/orders.ts`、`api/users.ts`、查询 key、15 秒轮询、分类常量、申请字段或路由。

## 大厅精确规格

- 标题区顺序：`订单大厅`、一句说明、右侧/同行可申请数量；手机不显示英文 kicker。
- 资格状态改成高度稳定的状态条：图标、等级、限制、原因、现有资料入口。可申请用翡翠弱背景，不可申请用金色弱背景。
- 分类 Segmented 横向滚动，容器不显示页面级滚动条；切换仍重置第 1 页。
- 桌面 1440px 三列，1024px 两列；卡片宽至少 280px，圆角 8px、1px 边框、无常驻阴影。
- 桌面图 16:10；手机卡按 PRD 8.3 的 104x104 摘要结构，不让图片独占一屏。
- 金额显示佣金与补贴构成；没有补贴时不占空行。商品来源、是否返货、素材数量和天数均必须可见。
- 详情按钮是唯一主按钮；已申请时按钮文案继续按当前状态显示。

## 详情精确规格

- 返回按钮为纯图标加可读标签，触控区 44px。
- 桌面图集与摘要为 7:5，主图比例 4:3，缩略图固定正方形；无图占位不改变尺寸。
- 摘要严格按 PRD 8.4 排列，`可获得收益` 显示总额并在下一行拆分佣金/补贴。
- 规格使用 2x2 描述网格，不做四张嵌套卡片。
- 申请状态块和主按钮互斥；资格不足时按钮禁用并显示原因。
- 手机主操作可做粘性操作栏，但底部必须位于达人导航之上，只能有一层固定操作。
- 申请 Modal 在手机宽度为 `calc(100vw - 24px)`，同款图上传、留言、取消和确认可达。

## 页面状态

逐一覆盖：加载骨架、无订单、接口错误、资格不足、未申请、待审核、被拒绝、已通过、提交中、提交失败、同款图缺失。接口错误不得显示为“暂无订单”。

- 390px 首屏至少能看到一张订单卡的主要判断信息和详情按钮。
- `npm test -- src/pages/orders/TalentMarketplace.test.tsx` 及新增测试、全量测试和构建通过。
