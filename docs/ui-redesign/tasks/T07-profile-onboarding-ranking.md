# T07 达人资料、入驻与榜单

## 目标

让身份认证、接单资料、收件信息、作品集和榜单更易理解，同时降低女性用户对隐私与审核的焦虑；一并完成共享 `ProfilePage` 的商家资料分支。所有字段、作品数量、等级规则和认证流程保持不变。

## 依赖与允许文件

- 依赖：T03。
- 允许修改：`frontend/src/pages/ProfilePage.tsx`、`frontend/src/pages/TalentOnboardingPage.tsx`、`frontend/src/pages/TalentRankingPage.tsx`、`frontend/src/components/TalentProfileFields.tsx`、对应测试、`frontend/src/styles/talent-account.css`。本页面断点写在该模块末尾。
- `ProfilePage` 的商家分支属于本任务，但只能调整现有店铺资料和实名认证的布局、状态与说明，不能添加字段或业务能力。
- 不允许修改用户 API、认证字段、地址常量、等级计算、榜单数据或路由。

## 个人资料规格

- 浏览态顺序：身份与认证、接单能力、收件信息摘要、作品集、维护入口。
- 头像 72px 手机/88px 桌面；昵称长文本可换行，不挤压状态标签。
- 身份证、支付宝、完整电话和详细地址不得在摘要态完整显示；编辑态旁写明真实用途。
- 接单能力使用一条三列摘要带，不做三张卡；手机可变为三行。
- 作品集为稳定方形网格，手机三列，桌面四列；图片失败有占位。

## 入驻规格

- 仍为“完善资料 -> 实名认证”两步，路径和提交顺序不变。
- Step 1 分组为基本资料、接单能力、收件信息、作品集；每组标题下仅一行用途说明。
- 作品集明确“至少 6 张、最多 12 张”，显示已上传数量；上传状态与 Form 值同步逻辑不变。
- Step 2 的真实姓名、身份证、支付宝账号和支付宝实名字段均说明用途与可见范围。
- 审核中、驳回、通过状态各只有一个主操作；驳回原因完整换行。

## 榜单规格

- Segmented 保持真实榜/演示榜及数据源不变。
- 真实榜强调已完成单数与收益；演示榜持续显示“平台演示”，不得使用“热门”“推荐”等暗示真实背书的文案。
- 前三名使用金、灰银、柔铜的细边框或序号，禁止皇冠大图、光效、渐变和夸张动画；现有 Crown 图标可缩为 18px。
- 等级规则使用紧凑说明带，不做三张营销卡。

## 商家资料分支

- 保留店铺名称、电商平台、联系电话、默认寄件地址和现有实名认证字段、校验及 API。
- 桌面使用主资料区与认证区两列，手机单列；长地址、电话错误和认证驳回原因完整换行。
- 不显示达人等级、接单能力、收件信息或作品集，不增加店铺营销装修能力。
- 联系电话和地址按当前用户自身权限展示；不得把商家敏感资料带到达人可见页面。

- [ ] 检查地址级联、上传、取消编辑、认证重提和榜单切换。

## 验收

- 6-12 张规则、字段名、地址转换、API 调用和认证跳转不变。
- 浏览态不暴露完整敏感信息，多行资料不遮挡操作。
- 演示榜与真实榜视觉和标签清楚区分。
- 商家资料字段、保存 API 与认证流程不变，手机端不横向溢出。
- 相关测试、全量测试和构建通过。
