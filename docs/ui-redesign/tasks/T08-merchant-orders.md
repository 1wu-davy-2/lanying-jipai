# T08 商家订单与多人履约工作台

## 目标

提高商家发布、查看订单和管理多个达人履约的效率，在手机网页提供可用摘要卡，同时保持运营审核申请、按名额履约和商家验收的现有边界。

## 依赖与允许文件

- 依赖：T01、T03。
- 允许修改：`frontend/src/pages/orders/MerchantOrdersPage.tsx`、`frontend/src/pages/orders/MerchantOrderWorkspacePage.tsx`、`frontend/src/components/OrderFulfillmentFormItems.tsx`、对应测试、`frontend/src/styles/merchant.css`。本页面断点写在该模块末尾。
- 不允许修改：订单 API、发布字段与校验、申请审核权限、履约状态、商家资料页面或路由。

## 订单列表与发布

- 标题、筛选/Tab 和“发布订单”保持现有行为；发布为唯一主操作。
- 桌面表格优先展示标题/订单号、招募名额进度、履约进度、佣金或预算、中文状态和创建时间。
- 手机改为订单摘要卡：标题+状态、订单号、招募/履约进度、金额、查看入口；不显示压缩宽表格。
- 发布 Modal 按“商品与合作、数量与费用、交付要求、样品处理”分组，字段顺序可分组但字段名、默认值、校验和 payload 不变。
- 数字字段手机单列；Switch 使用现有二元控件，不改为文本选项。

## 多人履约工作台

- 首区显示订单标题、父订单状态、招募名额与履约完成进度。
- Tabs/筛选保持现有值；名额卡按 `slot_no` 稳定排序。
- 每个名额卡只显示当前达人、履约状态、商品来源、下一步和进入详情按钮。
- Drawer 依次显示达人摘要、物流、素材版本/审核、留言；不再嵌套多层 Card。
- 素材验收“通过返图”为主操作，“驳回并要求修改”为危险次操作；只影响当前名额的说明必须保留。
- 申请列表继续显示运营审核结果。待审核项只提示到运营端处理，不新增商家审核按钮。

## 手机规格

- 使用 T03 的抽屉导航；页面左右 16px。
- 名额、申请和素材版本均使用可展开摘要，不依赖横向表格。
- Drawer 在 390px 全宽减 12px，关闭、返回和操作按钮至少 44px。
- 长物流单号、达人昵称、申请留言和审核意见可换行/复制，不溢出。

- 390px 能查看并操作单个名额，不显示其他名额的混合信息。
