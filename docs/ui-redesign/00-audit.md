# UI 与设计资产审查

## 1. 审查范围

本次审查覆盖 `docs/` 的产品、业务、前端和履约文档，`frontend/src/` 的路由、页面、组件与样式，及 `frontend/android/` 的图标、启动图和应用名称。审查目标是找出当前部署体验与目标用户之间的差距，不修改任何业务实现。

## 2. 结论摘要

当前问题不是单个页面“不够好看”，而是品牌、设计语言、响应式策略和业务真源同时分裂：达人端是冷静的深海青后台，未接入路由的官网是米灰植物杂志风，登录页使用摄影图加相机图标，Android 又同时保留鹰羽矢量标记与默认蓝色启动图。页面可以运行，但缺少一套从品牌入口到履约完成的连续体验。

已有达人端改版改善了信息层级，却仍然更像通用企业工作台。对首次接单的宝妈、大学生而言，信任、隐私、下一步和收益到账条件比“后台感”更重要。新设计应建立温和但专业的生活方式品牌感，不能只替换主色或增加圆角。

## 3. 关键发现

### 3.1 设计语言互相冲突

- `frontend/src/styles.css` 同时存在深海青达人系统与米灰、鼠尾草绿、陶土色官网系统，两者字体、圆角、阴影和信息密度完全不同。
- 全局 Ant Design 主题仅设置 `colorPrimary` 与 `borderRadius`，页面仍大量硬编码颜色。单一 CSS 文件共约 561 行、约 75 个不同十六进制色值，难以维护统一语义。
- 现有页面使用约 38 个 Card 和 10 个 Table，部分区域出现卡片套卡片、移动端横向滚动表格，视觉层级偏重且不利于快速扫读。

### 3.2 品牌资产不一致

- Web 标题和多数页面使用“蓝鹰寄拍”，`capacitor.config.ts` 与 Android `strings.xml` 使用“蓝影寄拍”。
- favicon 是植物枝叶图形，登录页以 `CameraOutlined` 作为品牌标记，Android 新版矢量资源是鹰羽勾形，部分位图和启动图仍是默认蓝色几何标记。
- 官网和登录页直接引用远程 Unsplash 图片，官网背景还依赖远程纹理。弱网或 Android WebView 断网时会出现空白或风格失真。

### 3.3 页面入口与文档失真

- `App.tsx` 将 `/` 重定向到 `/entry`，`OfficialHomePage` 有完整实现和测试，却没有活动路由。
- `docs/04-frontend-design.md` 页面清单漏掉达人榜单、多达人履约详情、运营发单、接单申请和话术库等当前页面。
- 旧业务文档仍描述“直接抢单”，当前实现已经是申请审核和多达人独立履约。UI 任务若照旧文档执行，会破坏现有流程。

### 3.4 手机体验覆盖不完整

- 达人端已有 56px 顶栏、五项底部导航和部分移动卡片，但大量规则仍靠单个 `760px` 断点处理。
- 商家与管理端在窄屏仍保留 224px 侧栏，多张表格仅依赖横向滚动，手机网页无法形成稳定的阅读与操作顺序。
- 缺少对 360/390/412px、Android 安全区、软键盘、长昵称、长订单标题、失败重试和弱网图片的统一要求。

### 3.5 信任体验不足

- 招募资料表明目标用户最关心是否收费、隐私是否安全、订单是否真实、何时结算；这些信息目前分散在 Alert、详情卡和文案中。
- 实名、支付宝、收件地址、作品集与交付素材涉及高敏感信息，页面没有统一的用途说明、脱敏样式和“谁可见”表达。
- 金额使用暖橙强调，但申请、履约、验收、结算的状态颜色与下一步表达未形成跨页面契约。

### 3.6 敏感品类仍缺少产品契约

- `docs/话术/sensitive-category-scripts.md` 已提出成年、自愿、可拒绝、用途限定与隐私边界，但当前数据库和页面没有完整的年龄、接单意愿、二次确认和退出字段。
- 这些能力涉及数据、权限与合规，不属于“功能流程不变”的视觉重设计。新 UI 只能保留现有敏感品类警示，不得用前端文案伪装成已完成的同意机制。
- 应单独立项确认成年校验、可见范围、主动订阅、拒绝后处理、投诉与数据留存，再修改接口和业务流程。

## 4. 必须保持的业务基线

- Android 继续承载同一套 React `dist`，不新增原生业务页面。
- `/` 继续跳转 `/entry`；官网组件是否成为正式首页需另行决策，本轮不得改路由。
- 达人仍按“资料与实名完成 -> 申请订单 -> 运营审核 -> 独立履约 -> 验收 -> 结算 -> 提现”执行。
- 多达人订单中，每位达人只能看到自己的物流、素材、反馈、留言和结算信息。
- 商家订单工作台只展示申请结果，申请审核仍由当前运营端完成。
- 不新增状态、字段、权限、承诺、消息、评分、支付网关或推送能力。

## 5. 新设计决策

1. 使用“莓果主色 + 翡翠信任色 + 中性白灰画布 + 少量金色金额”的多色语义系统，取代深海青单色后台感。
2. 女性用户是审美和信任设计依据，不是粉色化、卡通化或文案称呼依据。界面不直接称用户为“宝妈”“小姐姐”。
3. 达人端和登录入口优先优化；商家、管理端保持更高信息密度，但共享品牌、组件和状态语义。
4. 真实商品图、作品图和交付素材是主要视觉资产；装饰图不得压过可核对的信息。
5. 桌面使用侧栏，达人手机端使用底部导航；商家和管理端手机端改为抽屉导航，不压缩主内容。
6. 统一品牌名为“蓝鹰寄拍”，复用现有鹰羽勾形矢量作为唯一品牌标记。

## 6. 验证基线与限制

审查时已执行 `npm test` 和 `npm run build`，均通过。生产构建仍有 Ant Design 大包警告，但不是本轮视觉改版的阻塞项。

本次会话没有可用的现成浏览器连接，因此未对部署页面做截图式断言。实施阶段必须使用现有浏览器或人工真机进行视觉核验；环境没有该能力时要明确反馈“未进行可视化验收”，不得通过下载浏览器自动化依赖绕过限制。
