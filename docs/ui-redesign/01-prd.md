# 蓝鹰寄拍全端 UI 重设计 PRD

> 状态：可执行基线
>
> 日期：2026-08-06
>
> 范围：Web、手机 Web、Capacitor Android 视觉层

## 1. 文档目的

本 PRD 定义蓝鹰寄拍网页、手机网页和 Capacitor Android 的统一视觉体验。业务流程、页面路由、权限、接口、字段与状态机保持不变，只调整视觉系统、信息层级、响应式布局、组件表现、状态反馈和辅助文案。

本 PRD 的视觉规范取代旧“深海青・稳妥亲和”方案及旧官网植物杂志风；旧文档中的业务规则仍有效。

## 2. 用户与场景

### 2.1 用户假设

- 约 85% 的最终用户为女性，核心为宝妈、大学生和希望灵活参与寄拍的女性。
- 她们不一定熟悉电商后台、状态机或物流术语，通常使用 360-412px 的手机或 Android App。
- 首次使用时最关注：平台是否可信、是否要先付费、商品如何处理、要交付什么、个人资料谁能看到、收入何时可提现。
- 商家和运营用户频次更高、桌面使用更多，需要密度、批量扫读和风险识别，而不是营销式页面。

“女性占比 85%”作为当前产品假设记录，后续应以用户访谈和数据验证；不得据此将界面低龄化或过度粉色化。

### 2.2 设计目标

1. 用户在订单卡首屏 5 秒内能找到收益、商品来源、交付时限、素材要求和申请状态。
2. 每个履约状态只突出一个下一步主操作，历史和解释退居次级。
3. 入口、达人端、商家端、运营端和 Android 品牌资产看起来属于同一产品。
4. 360px 至 1440px 无内容遮挡、不可恢复的横向溢出或底部导航覆盖。
5. 敏感资料和金额状态可核对，页面不制造后台无法兑现的承诺。

### 2.3 非目标

- 不新增或删除页面、路由、导航项、接口、字段、角色、权限或订单状态。
- 不改变申请审核、多人履约、物流、验收、结算和提现逻辑。
- 不开发 iOS、小程序、原生 Android 业务页面、聊天、评价、支付或通知。
- 不将未接入路由的官网组件切换为 `/` 首页。
- 不为视觉改版引入新的 UI 框架、图标库、动画库或浏览器测试依赖。

## 3. 产品体验原则

### 3.1 温和但不幼稚

以清晰排版、真实图片、柔和底色和克制动效表达亲和感。避免爱心、蝴蝶结、卡通人物、大面积粉色、花哨渐变、装饰性光斑和“小姐姐”等称呼。

### 3.2 可信比热闹重要

规则、隐私、商品处理、审核主体、结算条件必须就近显示。禁止使用“稳赚”“轻松月入”“平台兜底”等未被业务实现支持的表达。

### 3.3 下一步优先

列表先显示状态和下一步，详情先显示当前阶段、所需凭证、截止条件和唯一主操作。历史记录、说明和重复字段折叠到下一层。

### 3.4 图片服务于判断

订单图必须展示真实商品；作品集展示真实拍摄能力；交付区展示可审核素材。无图时使用带分类图标的低调占位，不使用与商品无关的氛围图。

### 3.5 同一语义跨端一致

同一个状态、金额、主操作、禁用原因和风险提示在桌面、手机网页和 Android 中使用相同颜色、图标、文案和顺序。

## 4. 品牌与视觉系统

### 4.1 品牌名称与标记

- 唯一中文名：`蓝鹰寄拍`。
- 唯一图形：现有 Android 鹰羽勾形矢量，复用其轮廓制作 Web Logo、favicon、Android 自适应图标与启动图。
- Logo 组合：图形在左、中文名在右；紧凑区域只显示图形，但必须有 `aria-label="蓝鹰寄拍"`。
- 功能图标继续使用已有 `@ant-design/icons`，不得用 emoji、Unicode 箭头或临时手绘 SVG 代替常见功能图标。

### 4.2 色彩令牌

白字与主色、信任色的对比度均高于 5:1。状态不得只依赖颜色，必须同时显示文本；关键状态可配 16px 图标。

### 4.3 字体与排版

- 字体栈：`"Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`，不依赖在线字体。
- 页面标题：桌面 28px/36px、手机 24px/32px，字重 700。
- 区块标题：20px/28px，字重 650-700。
- 卡片标题：16px/24px，字重 650。
- 正文：15-16px/24px；辅助文字 13px/20px；不得小于 12px。
- 金额：使用等宽数字特性 `font-variant-numeric: tabular-nums`；主金额 28-32px，列表金额 18-20px。
- 字号不得随视口连续缩放；中文不使用负字间距。

### 4.4 间距、圆角与阴影

- 间距阶梯：4、8、12、16、24、32、40、48px。
- 表单与卡片内部默认 16px，桌面主要区块 24px；移动端页面左右 16px。
- 控件圆角 6px，卡片与弹层 8px；圆形仅用于头像、状态点和纯图标按钮。
- 普通页面以边框和留白分区，不把整段页面做成漂浮卡片，不使用卡片套卡片。
- 阴影仅用于抽屉、弹层、固定导航和悬浮中的可点击卡片；普通内容卡无阴影。

### 4.6 图片规范

- 官网和认证入口使用自然光、真实居家或校园创作场景，展示真实人物与商品，不使用暗色、过度裁切或纯氛围库存图。

- 品牌图存放于 `frontend/public/images/brand/`，订单与用户图片继续使用 API URL。
- 品牌图使用 WebP，桌面宽图单张建议不超过 250 KB，手机图不超过 160 KB；提供明确 `alt`。
- 禁止依赖远程纹理和运行时第三方图片 URL。图片加载失败必须显示稳定占位，不改变布局。

## 5. 响应式框架

### 5.1 验收宽度

必须检查 360、390、412、768、1024 和 1440px。390x844 是 Android 与手机网页的主验收尺寸，1440x1000 是桌面主验收尺寸。

### 5.2 布局规则

- 1440px：工作台侧栏 232px，内容最大宽度 1200px，页面内边距 32px。
- 1024px：侧栏 216px，内容内边距 24px；三列卡片可降为两列。
- 768px：达人端进入移动导航；商家与管理端侧栏改为抽屉，不得挤压内容。
- 360-412px：页面左右 16px，区块间距 24px，主按钮可满宽，筛选器可横向滚动但页面本身不得横向滚动。
- 手机顶部栏 56px；达人底部导航为 `64px + env(safe-area-inset-bottom)`；正文底部留白至少为 `88px + env(safe-area-inset-bottom)`。
- 固定主操作存在时，置于底部导航上方，不能同时出现第二个固定操作层。

### 5.3 触控与键盘

- 触控目标至少 44x44px，相邻目标至少 8px 间距。
- 键盘弹出时表单当前字段和提交按钮仍可滚动到可见区域。
- 抽屉、弹层打开后聚焦进入，关闭后焦点返回触发控件；Esc 和 Android 返回键按现有容器行为关闭当前层级。

## 6. 全局组件契约

### 6.1 页面标题

顺序固定为：可选返回按钮、标题组、状态/主操作。标题组包含页面标题和一句不超过 24 个汉字的说明。手机端操作空间不足时，主操作换到标题下方满宽，不压缩标题。

### 6.2 按钮

- 每个视口区域最多一个主按钮。
- 次要操作使用默认按钮或文字按钮；破坏性操作使用危险样式并二次确认。
- 禁用按钮附近必须说明原因，例如“完成实名认证后可申请”，不能只置灰。
- 提交中保持按钮宽高稳定并阻止重复提交。

### 6.3 状态标签

- 申请：待审核用蓝色，已通过用翡翠色，已拒绝用红色。
- 履约：待动作使用金色，进行中用蓝色，已完成用翡翠色，争议/取消用红色或中性灰。
- 状态标签统一中文映射，禁止管理页面直接显示英文枚举。
- 标签高度 24px，最多一行；长状态使用文字说明，不压缩到不可读。

### 6.4 表格与列表

- 桌面高频运营页面保留表格；表头使用中性底色，行 hover 不改变高度。
- 手机端不得直接缩小完整表格。达人端使用任务卡；商家和运营端使用摘要行或可展开卡，保留关键操作。
- 列表项固定显示主对象、状态、关键金额/时限和下一步；订单号、时间等作为次要信息。

### 6.5 表单

- 标签置于字段上方，必填使用统一标记；帮助文字写明用途而不是重复字段名。
- 身份证、支付宝、手机号和地址字段旁显示用途与可见范围；回显时按现有权限脱敏。
- 错误信息紧邻字段，保留用户已填内容；页面顶部仅汇总跨字段或服务端错误。
- 上传区显示数量、格式、大小、上传中、成功、失败和重试状态，容器尺寸不随状态跳动。

### 6.6 页面状态

所有数据页都要有：加载骨架、正常、空、接口错误、无权限/数据不存在、提交中、提交成功和提交失败状态。空状态必须提供真实可执行入口；接口失败提供“重新加载”，不得伪装为空数据。

### 6.7 弹层

- 桌面使用 Modal/Drawer；手机 Modal 宽度不超过 `calc(100vw - 24px)`，长表单优先全宽抽屉或页面内流程。
- 标题、说明、主次按钮顺序一致；危险确认说明影响对象和不可逆结果。
- 不使用 `window.innerWidth` 在渲染时硬算宽度，改用 CSS 响应式宽度或组件支持的响应式配置。

## 7. 信息与信任文案

### 7.1 语气

直接、尊重、可核对。使用“接单申请”“交付素材”“审核中”“预计条件”而不是“抢赚”“轻松搞定”“绝对安全”。不在界面中称呼用户为宝妈、学生或女性。

### 7.2 固定表达

- 费用：只根据真实订单显示押金、购买支出、补贴和佣金；没有费用时写“本单无需缴纳押金”。
- 隐私：写明“仅用于实名认证/寄送样品/结算审核”，不得泛称“绝对保密”。
- 审核：明确“由运营审核申请”“由商家/运营按当前实现验收”，不混用主体。
- 收益：区分佣金、商品补贴、待结算、可提现和处理中提现；不同字段不得合并为虚假的“累计收益”。

## 8. 页面规格

### 8.1 `/entry`、登录与注册

- 入口首屏显示统一 Logo、明确标题、两个现有工作台入口；顺序和路由保持不变。
- 桌面为真实创作场景图片与表单并列，比例约 5:4；手机端图片缩为 120-144px 品牌横幅，表单立即进入首屏。
- 登录表单宽度 400px，手机满宽；密码可见性、错误、加载和入口身份提示稳定。
- 达人注册突出“创建接单账号”，不得添加邀请码、营销承诺或未存在的协议勾选。

### 8.2 达人工作台壳层

- 桌面侧栏显示统一 Logo、五个带图标导航项、当前项莓果底色；用户和退出位于底部或顶栏稳定区域。
- 手机顶部栏仅显示品牌、当前用户与退出图标；底部五项导航保持现有顺序和路由。
- 当前页、详情页和钱包子页必须正确高亮父导航。

### 8.3 订单大厅 `/model/hall`

- 首屏顺序：标题与订单数、资格/认证状态、分类筛选、订单列表。
- 桌面使用 3 列为主的商品卡；手机使用紧凑任务卡，不让 4:3 大图占满首屏。
- 卡片固定顺序：真实商品图、分类/商家保障、标题、总可得金额、商品来源、商品处理、交付数量、交付天数、要求摘要、唯一详情按钮。
- 资格 Alert 改为轻量状态带；不可申请时显示原因与“去完善资料”现有入口，不隐藏订单。
- 15 秒轮询、分类、分页和申请状态保持不变。

手机卡片参考：

```text
┌──────────────────────────────┐
│ 104x104 商品图 │ 分类 / 保障 │
│                │ 标题（两行）│
│                │ 可得 ¥188   │
├──────────────────────────────┤
│ 商家寄样 · 拍完返货 · 5 天   │
│ 6 张图 + 1 视频 / 要求摘要    │
│ [查看详情并申请]              │
└──────────────────────────────┘
```

### 8.4 大厅详情与申请 `/model/hall/:id`

- 桌面为商品图 7/12、订单摘要 5/12；手机先图后收益与主操作。
- 摘要顺序：标签、标题、可获得收益及构成、四项关键规格、申请状态、主操作、禁用原因。
- 下方顺序：你需要完成、如何完成、订单保障与规则、合作商家。
- 申请弹层保留留言和同款图上传逻辑；手机键盘弹出时确认按钮可见或可滚动到达。
- 已申请、被拒、已通过和资格不足使用不同状态块，不能同时显示矛盾主操作。

### 8.5 我的订单与履约详情

- `/model/orders` 桌面表格、手机任务卡；Tab 可横向滚动且保持当前选择。
- 每项显示标题、订单号/名额、收益、中文状态、下一步，不显示其他达人信息。
- `/model/fulfillments/:id` 与旧订单详情突出“当前阶段 -> 下一步 -> 所需材料/物流 -> 主操作”，时间线和留言置后。
- 交付素材固定缩略图比例，视频有播放标识；修改意见与版本号就近显示。
- 待收货、拍摄中、要求修改、待验收、已完成和争议状态必须逐一验收。

### 8.6 钱包与提现

- 钱包首屏主数据为可提现余额；处理中提现和账单笔数降一级，不虚构累计收益。
- “申请提现”是唯一主操作；余额不足或资料不完整时显示真实禁用原因。
- 桌面保留资金明细和提现进度表格；手机改为账单列表，金额、状态、时间和驳回原因不横向滚动。
- 提现表单显示本次金额、可提现余额、收款账户快照含义和提交后流程。

### 8.7 个人资料、入驻与榜单

- 个人页顺序：身份与认证、接单能力、收件信息摘要、作品集、编辑入口；隐私字段不在浏览态完整展示。
- 入驻仍为“接单资料 -> 实名认证”两步，保留 6-12 张作品规则和所有现有字段。
- 每个资料分组说明用途；认证中、被驳回、已通过分别只提供一个合理下一步。
- 榜单明确“真实榜/平台演示榜”，演示数据不得像真实收益背书；前三名可有克制的金银铜强调，不使用奢华营销视觉。

### 8.8 商家端

- 保留订单发布、订单列表和多人履约工作台的现有功能。
- 订单列表突出招募进度、履约进度、预算和状态；桌面表格，手机摘要卡。
- 多人履约工作台以名额为主对象，申请、物流、素材版本、验收和留言不得混成一个长卡片。
- 商家看到的申请审核入口继续说明“由运营端审核”，不得新增商家审核动作。
- 店铺资料保留店铺名称、平台、联系电话、默认寄件地址和实名认证；桌面两列、手机单列，敏感字段不出现在达人可见区域。

### 8.9 管理端

- 桌面优先、密度适中。侧栏按订单运营、用户资金、内容支持形成视觉分组，但导航项、路径和权限不变。
- 运营发单、接单申请、订单监控和争议处理优先突出待处理数量、风险与当前操作。
- 看板数据不使用营销大卡；使用紧凑指标行和趋势/说明区域，空数据明确。
- 用户、提现和话术库在手机端提供可展开摘要，不强迫查看宽表格。
- 英文状态枚举必须通过已有映射展示为中文。

### 8.10 官网组件

- `OfficialHomePage` 作为未接入路由的品牌组件继续维护，视觉改为与工作台一致的莓果/翡翠系统。
- 品牌名必须是首屏主信号，真实寄拍场景作为全宽或沉浸式主视觉，不保留植物线稿、远程纸张纹理和大圆角杂志卡。
- 官网重设计不得修改 `App.tsx` 的 `/` 重定向，不得宣称尚未提供的小程序或下载能力已经上线。

### 8.11 Android 外壳

- `appName`、`app_name` 和界面统一为“蓝鹰寄拍”。
- 自适应图标、旧版图标、启动图与 Web Logo 使用同一鹰羽勾形；移除默认蓝色几何标记。
- 启动背景使用 `#F7F7FA`，标记使用 `#B33B5A` 与 `#26756F`，不加入营销文案。
- WebView 继续加载同一 `dist`，保留 HTTPS 和强制更新逻辑。

## 9. 可访问性与隐私

- 正文和控件达到 WCAG 2.1 AA 对比度；焦点环清晰，不以 hover 作为唯一反馈。
- 所有图片有语义化 `alt`；装饰图片使用空 `alt`；视频控件可键盘使用。
- 导航、表单、弹层、Tabs 和上传控件具备可读名称；状态变化使用现有 Ant Design 消息能力并保留页面内结果。
- 支持 `prefers-reduced-motion`；动效 120-220ms，不使用循环装饰动画。
- 身份证、支付宝、电话、详细地址只对当前有权限的用户显示，列表默认脱敏；多达人场景严格隔离。

## 10. 性能与工程约束

- 不新增运行时依赖；继续使用 React、Ant Design、现有图标库和 CSS。
- 品牌图片本地化并懒加载；首屏关键图明确尺寸，避免布局位移。
- 样式按基础、认证、工作台、达人、商家、管理和官网拆分，避免继续扩大单一 CSS 文件。
- 不在 JSX 新增颜色和尺寸内联样式；可变业务值除外。
- 本轮不以拆包为目标，但新增代码不得让现有主包警告显著恶化。

## 11. 验收标准

1. 所有现有测试和 `npm run build` 通过，业务断言不被删除或弱化。
2. 当前路由、导航 key、API 函数、查询 key、表单字段和状态转换不变。
3. 360/390/412/768/1024/1440px 无页面级横向滚动、文字遮挡、按钮溢出或固定导航覆盖。
4. 达人端关键流程在手机上可单手完成：登录、浏览、申请、查看订单、收货/交付、钱包、资料与提现。
5. 商家和管理端在手机上可以完成紧急查看与单项操作，桌面保留高效扫读。
6. Logo、名称、favicon、启动图、导航图标、色彩与状态语义跨端一致。
7. 所有页面具备加载、空、错误和禁用原因；敏感资料说明与多达人隐私边界明确。
8. 页面审查不安装或下载 Playwright/Chromium；环境无现成浏览器时如实记录未完成的视觉验收。

## 12. 发布与度量建议

本轮先灰度给内部运营和少量达人，记录大厅到详情点击率、申请完成率、入驻完成率、交付错误率和提现咨询量。上线后一周访谈至少 5 名首次接单用户，其中覆盖学生与育儿女性，重点验证信任理解、隐私顾虑、订单要求识别和下一步可发现性。该度量建议不要求本轮新增埋点。
