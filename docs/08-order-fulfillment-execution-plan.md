# 订单履约规则升级执行方案

## 1. 目标与范围

本方案覆盖商家发单、达人申请、寄样或自购、拍摄返图、验收结算的完整履约链路。目标是让每一笔订单在发布时就明确商品获取方式、是否返货、补贴金额和素材标准，并让平台、商家、达人都能追踪其状态。

本轮范围：

- 支持商家寄样、达人自行购买、达人已有同款三种商品获取方式。
- 支持“拍完自留”和“需返货”两种履约规则。
- 自行购买订单必须配置每单不少于 12 元的商品补贴。
- 已有同款订单必须先由商家审核同款照片，再进入拍摄。
- 返图必须满足规定图片数量，且至少包含一条时长大于 5 秒的视频。
- 抢单大厅展示商品来源、返货规则、补贴、优质商家和保证金标签。

## 2. 订单履约规则

| 商品获取方式 | 商家动作 | 达人动作 | 是否返货 | 后续状态 |
| --- | --- | --- | --- | --- |
| 商家寄样 | 审核申请后寄出样品 | 收货、拍摄、上传素材 | 商家在发单时选择；不返货即拍完自留 | `CLAIMED -> SHIPPED_TO_MODEL -> IN_PROGRESS` |
| 达人自行购买 | 审核申请后无需寄样 | 自行购买商品、拍摄、上传素材 | 不返货，拍完自留 | `IN_PROGRESS` |
| 达人已有同款 | 审核达人提交的同款照片 | 上传同款照片，审核通过后拍摄 | 不返货，拍完自留 | `OWNED_PRODUCT_REVIEW -> IN_PROGRESS` |

约束如下：

- `talent_purchase` 必须填写 `product_subsidy_amount >= 12.00`。
- `talent_purchase` 和 `talent_owned` 不能要求返货，且强制标记为拍完自留。
- `merchant_ship` 可以选择返货；若不返货，订单标记为拍完自留。
- 达人已有同款时，申请中最多提交 6 张同款实拍图；商家拒绝后订单重新开放，达人可补图后再次申请。

## 3. 状态机与责任边界

```text
PUBLISHED
  |- 商家寄样申请审核通过 -> CLAIMED -> SHIPPED_TO_MODEL -> IN_PROGRESS
  |- 达人自行购买申请审核通过 -> IN_PROGRESS
  |- 达人已有同款申请审核通过 -> OWNED_PRODUCT_REVIEW
                                          |- 商家通过 -> IN_PROGRESS
                                          `- 商家驳回 -> PUBLISHED

IN_PROGRESS
  |- 需返货：达人提交图片、视频和返货物流 -> RETURNED
  `- 拍完自留：达人提交图片和视频 -> RETURNED

RETURNED
  |- 商家验收通过 -> COMPLETED -> 佣金和商品补贴结算
  `- 商家验收不通过 -> DISPUTED
```

责任划分：

- 商家：设置订单规则、审核达人申请、审核同款照片、验收素材。
- 达人：根据订单规则申请、上传同款凭证或交付素材、按要求返货。
- 管理员：配置商家优质标签和保证金标签，处理争议、异常订单和资金审核。
- 服务端：以状态机和数据校验作为最终准入条件，前端提示不能替代服务端校验。

## 4. 数据与迁移计划

### 4.1 `orders`

新增字段：

- `product_source`：`merchant_ship`、`talent_purchase`、`talent_owned`。
- `product_subsidy_amount`：商品补贴，默认 `0.00`。
- `self_keep_after_shoot`：是否拍完自留。

### 4.2 `order_applications`

新增 `owned_product_images`，以 JSON 数组保存达人已有同款的上传凭证。

### 4.3 `merchant_profiles`

新增以下平台运营属性：

- `quality_merchant`：优质商家标识。
- `guarantee_deposit_paid`：是否已缴纳保证金。
- `guarantee_deposit_amount`：保证金金额。

### 4.4 `media_assets`

建立媒体资产表，记录上传人、URL、文件类型和视频时长。交付时以该表校验素材归属，防止达人提交他人链接或伪造视频时长。

### 4.5 发布顺序

1. 先执行数据库迁移，新增字段和 `media_assets` 表。
2. 更新初始化 SQL，保证新环境一次初始化即可得到完整结构。
3. 发布后端接口和状态机规则。
4. 发布前端表单、详情页和大厅标签。
5. 对已发布旧订单按 `merchant_ship`、补贴 `0`、不自留的兼容默认值处理。

## 7. 接口清单

| 功能 | 接口 | 角色 |
| --- | --- | --- |
| 发布订单 | `POST /api/orders` | 商家 |

## 8. 验收标准

1. 自行购买订单的补贴低于 12 元时，前端提示且服务端返回校验失败。
2. 自行购买和已有同款订单不能被配置为需返货。
3. 已有同款订单在商家审核前不能进入拍摄；驳回后可重新申请。
4. 提交交付时少图片、没有视频、视频不属于当前达人或视频时长小于等于 5 秒，服务端均拒绝。
5. 需返货订单没有快递公司或单号时不能提交；拍完自留订单无需填写返货物流。
6. 商家验收通过后，达人钱包入账金额等于订单佣金加商品补贴。
7. 抢单大厅可清晰展示返货、自购/已有同款、补贴、优质商家和保证金标签。
8. 老订单在迁移后仍可按原寄样返货流程完成。

## 9. 风险与回滚

- 视频时长以服务端解析的 MP4 元数据为准；无法解析时不允许作为合格视频提交。
- 同款凭证和交付素材均按上传者校验，避免跨账号复用 URL。
- 订单状态转换只允许在服务端状态机中发生，禁止前端直接改状态。
- 数据库迁移前先备份生产库；如需回滚应用版本，保留新增字段和表结构，应用通过默认值继续读取，避免直接删除已有履约数据。
