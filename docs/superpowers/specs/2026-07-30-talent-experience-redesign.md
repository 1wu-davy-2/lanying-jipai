# 达人端正规化体验设计规格

## 决策

采用 A 方案“深海青 · 稳妥亲和”，覆盖达人端网页、移动网页和 Android WebView：订单大厅、订单详情、我的订单、钱包、个人资料与入驻流程。

## 目标用户与结果

主要用户是首次接单的学生和宝妈。页面应首先传达订单规则、佣金、样品处理方式和平台审核状态，其次才是商品内容。视觉不采用可爱化、促销化或夸张收益表达；用户应能在一次扫读中判断“能不能接、做什么、多久交付、钱何时到账”。

成功标准：

- 桌面与 390px 宽移动端的关键操作均不折行、不遮挡，状态和金额可快速扫描。
- 所有“平台保障”文案仅复述已有业务规则，不新增后端无法兑现的承诺。
- 订单申请、履约、钱包和认证状态使用同一套深海青语义与暖橙金额强调。
- Android 继续加载同一套 `dist` Web 资源，无 API、数据库或 Capacitor 网络策略变化。

## 信息架构与页面规则

### 订单大厅

- 导航文案由“抢单大厅”调整为“订单大厅”，避免营造无序抢单感。
- 顶部显示可申请数量和当前资格状态；未认证时直接说明待完成资料，不隐藏限制原因。
- 订单卡片固定顺序：商品图、分类、佣金、标题、样品数量/素材要求/交付期限、交付要求、查看或申请按钮。
- 商品图片始终显示实际样品图；无图时才使用低调的分类空态。

### 订单详情与我的订单

- 详情按“收益与订单状态、交付规格、样品处理、平台审核规则、拍摄与交付要求、合作商家”排序。
- 已申请、已分配、寄样、交付和验收均使用现有状态机；页面只将当前状态转换为清晰的下一步说明。
- 我的订单在移动端使用可点击订单行，突出当前状态、佣金和下一步；桌面保留表格以便扫描。

### 钱包

- 将可提现余额作为唯一主数据，冻结金额和提现状态放在相邻但低一级的位置。
- 流水表和提现记录保持账单式排版，正向金额用佣金橙，扣减和审核状态使用明确文字与现有状态标签。
- 不显示虚构的预计到账时间或资金担保承诺。

### 个人资料与入驻

- 个人资料上方固定展示认证状态、等级、已完成订单、进行中订单和单笔上限；联系方式与收货地址保持编辑态可见、浏览态简洁。
- 入驻仍为两步：接单资料、实名认证。每一步说明其用途和审核后的结果，身份证与支付宝字段只在必要的认证步骤出现。
- 作品集规则明确保留“至少 6 张、最多 12 张”，上传状态必须与 Form 字段同步。

## 跨端与非目标

- React 页面是网页和 Android 的唯一 UI 源；Android 只执行 `npm run android:sync` 同步 Web 构建产物。
- 本轮不新增消息、评分、支付网关、推送、Native 页面、路由或任何后端 API。
- Android 编译环境要求 JDK 21。当前开发机仅有 JDK 17，安装/指定 JDK 21 是构建前置条件，不通过降低项目 Java 版本规避。

## 验收

1. 1440x1000 与 390x844 Chromium 截图中，文字、金额、固定导航和订单图片均清晰且无重叠。
2. 订单大厅到详情申请、管理员审核、履约、结算、提现和移动端导航的既有 E2E 流程仍通过。
3. 前端单测、TypeScript/Vite 生产构建通过；Android 在 JDK 21 环境完成 `assembleDebug`。
